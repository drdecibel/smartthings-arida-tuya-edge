# Changelog

## 0.3.0 – 2026-10-23

- No typing: `tools/push-keys.py` sends device IDs and local keys from tinytuya's
  `devices.json` to the hub over the local network. The driver asks with a UDP broadcast
  during Scan nearby and at start-up, stores the keys on the hub and creates one device
  per ventilator. Device settings still work and take precedence.

## 0.2.0 – 2026-10-23

- Units can stay on DHCP. A unit is identified by its device ID and local key; the driver
  finds its address by scanning the hub's /24 for TCP 6668 and asking each host with the
  unit's key, and searches again when the address stops answering. **IP-adresse** is now
  optional (`auto`) and pins the unit when set.
- Protocol preference keys are `v33`/`v34`/`v35`; the SmartThings API rejects `3.3`.
- Documented the Base WiFi's data points as read from real units.

## 0.1.0 – 2026-10-23

First release, not yet verified on hardware.

- Local control of Arida Base/Venti WiFi ventilators over the Tuya local protocol.
- Tuya protocol 3.3, 3.4 and 3.5 with automatic detection. Every frame, handshake
  and session key is checked against vectors generated by tinytuya.
- Switch, fan speed (1–3), mode (heat recovery/supply/exhaust), humidity or CO₂
  reading, temperature, filter status, sensor control and boost.
- Humidity or CO₂ threshold as a device setting.
- Automatic switch between the humidity and CO₂ profiles.
- Configurable DP numbers for firmware that numbers data points differently.
- Several units: each "Scan nearby" adds one device once the previous ones are configured.
